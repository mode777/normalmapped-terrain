# Synthetic biome world

The `biome.html` scene renders a compact, checked-in synthetic world. It exists
to prove that the material stack, shader and pre-baked tile pipeline cover
several biomes at once without growing the stack format or fetching textures at
runtime.

## World

| Field | Value |
|---|---|
| Extent | 15.36 km × 15.36 km |
| Local frame | centred at `(0,0)`; `+x` east, `+z` south, row 0 north |
| L0 mesh spacing | 15 m |
| Height grid | 1,024 × 1,024 samples at 15 m |
| LODs | 5 (`S0 = 15 m`) |
| Tile size | 64 height samples |
| Normal scale | 2× (7.5 m normal texels) |
| Tile cache | 5 × 5 slots per LOD |
| Height scale | 2,600 m for normalized height 1 |
| Seed | `20261105` |
| Checked-in size | ~18.5 MB (height/normal tiles, stack, macro, map and report) |

The world is deliberately as small as it needs to be: six biome bands are
about 2.56 km wide, enough to traverse and compare palettes, while the tile
count stays at 344 and the normal PNGs stay manageable. The high peaks and the
colder biomes are in the north; the south is lower and warmer.

## Biome order

Climate is a warped north–south coordinate. Six equal bands give the region
order:

1. Arctic
2. Tundra
3. Boreal
4. Temperate
5. Arid
6. Tropical

Temperature and moisture are secondary fields used by the material rules.
Arctic/tundra snow, temperate forest floor, arid sand and tropical laterite are
selected from the same packed Poly Haven library as the Jotunheimen scene.

## Material palettes

Each region owns four material IDs. The checked-in stack stays four slots, so
the same shader and texture layout cover every biome.

| Region | Materials |
|---|---|
| arctic | `snow_02`, `snow_field_aerial`, `rock_face_03`, `rocky_terrain_02` |
| tundra | `rock_pitted_mossy`, `lichen_rock`, `sparse_grass`, `rock_face_03` |
| boreal | `forest_ground_04`, `brown_mud_leaves_01`, `mossy_rock`, `rock_face_03` |
| temperate | `leafy_grass`, `forest_ground_04`, `brown_mud_03`, `rock_face_03` |
| arid | `sand_01`, `dry_ground_rocks`, `sandstone_cracks`, `rock_face_03` |
| tropical | `forest_leaves_02`, `red_laterite_soil_stones`, `leafy_grass`, `rock_face_03` |

The six palettes use 17 of the 20 packed materials; `gravelly_sand`,
`aerial_grass_rock` and `aerial_beach_01` remain available for tuning without
changing the manifest contract.

### Transition bands

Each adjacent pair has a fixed four-ID band palette:

| Band | Materials |
|---|---|
| arctic–tundra | `rock_face_03`, `snow_02`, `rock_pitted_mossy`, `rocky_terrain_02` |
| tundra–boreal | `rock_face_03`, `rock_pitted_mossy`, `forest_ground_04`, `mossy_rock` |
| boreal–temperate | `rock_face_03`, `forest_ground_04`, `leafy_grass`, `brown_mud_03` |
| temperate–arid | `rock_face_03`, `leafy_grass`, `sand_01`, `dry_ground_rocks` |
| arid–tropical | `rock_face_03`, `sand_01`, `red_laterite_soil_stones`, `forest_leaves_02` |

Every band is 720 m wide. A region material that is not in the adjacent band
palette is faded to zero over the 384 m before the band edge. At the edge, the
region's remaining weights equal the band's restricted weights, so the ID set
can switch from the region palette to the band palette without a visible pop.
Inside the band the two restricted weight vectors are blended by the smoothed
climate progress. `rock_face_03` is in every region and band, so cliffs stay
rock across the world.

The stack is baked from the quantized 15 m L0 grid, not the raw float field.
That is what lets `--materials-only` reconstruct the same grid from the checked-in
height tiles and reproduce the stack hashes exactly.

## Macro, biome map and report

```
stack-ids.png      2048^2 RGBA8   four library indices per texel
stack-weights.png  2048^2 RGBA8   four normalized weights (sum 255)
macro-albedo.png   1024^2 RGBA8   weighted palette average + low-frequency noise
biome-map.png      1024^2 RGBA8   R=region, G=transition+1, B=progress, A=climate
biome-report.json                 region/transition texel counts, weight means,
                                  edge jumps and non-band weights
```

The macro map is sampled from the same palette/transition function at 15 m /
texel and blended with a low-frequency variation. The runtime uses it beyond
the material texture fade, so distant terrain keeps the biome color instead of
becoming one alpine tint.

The biome map is QA/legend data, not a runtime shading input. Row 0 is north,
matching the height and stack PNGs (`flipY = false`).

## Source and license

The world is generated by `tools/biome/world.ts` from the seed above. The
height field is a pure `(x,z)` function built from the shared terrain composer;
the bake samples it once into the global grid. No source DEM or runtime
procedural work is involved.

The generated dataset is released under the repository's MIT license. The
packed material textures are Poly Haven CC0 assets; see
[`../public/materials/README.md`](../public/materials/README.md).

## Output layout

```
public/data/biomes/
  manifest.json
  coarse-height.bin          # 1024^2 uint16 normalized heights
  seam-report.json
  preview.png                # 512^2 biome-colored hillshade
  h/<level>/<tx>_<ty>.bin    # 64^2 uint16 little-endian, normalized
  n/<level>/<tx>_<ty>.png    # 128^2 RGBA8 object-space normals
  stack-ids.png              # added by the material stack bake
  stack-weights.png          # added by the material stack bake
  macro-albedo.png           # added by the material stack bake
  biome-map.png              # added by the material stack bake
  biome-report.json          # added by the material stack bake
```

The manifest records the synthetic source (`generator`, `seed`, `version`),
the local frame, height range, tile ranges, encodings, coarse-grid metadata,
bake version and seam report. Runtime paths are derived from the `h/` and `n/`
patterns; there is no per-file list.

## Commands

```bash
# Bake the world into public/data/biomes
npm run bake:biome

# Bake into a temporary directory
npm run bake:biome -- --out /tmp/biome-bake

# Rebake only the material stack/macro/map from checked-in L0 tiles
node tools/bake-biome.ts --config tools/biome/config.json --materials-only

# Rebake materials into a temp directory and compare hashes
node tools/bake-biome.ts --config tools/biome/config.json --check-materials

# Validate the checked-in dataset without network access
npm run test:biome

# Validate only the generator/tile/climate logic before a dataset exists
npm run test:biome -- --synthetic

# Validate a non-default output directory
node tools/bake-biome.ts --config tools/biome/config.json --check --out /tmp/biome-bake
```

`npm run bake:biome` uses the checked-in packed material library at
`public/materials/manifest.json`; it never calls the Poly Haven API. If a
palette references a missing material, the bake fails instead of downloading
it. Run `npm run bake:materials` only when the packed library itself changes.

## Validation

`npm run test:biome` runs the synthetic world checks and then validates the
checked-in dataset:

1. the height/climate functions are deterministic and in range;
2. every biome has non-zero sample coverage and the climate axis is monotonic
   along the north–south line;
3. tile ranges, height tiles and LOD samples agree with the global grid;
4. adjacent normal tiles share the same boundary reference;
5. every height/normal/coarse/seam file exists with the declared dimensions;
6. the seam report is within its threshold;
7. every stack ID quartet is one of the six palette or five transition sets;
8. every texel's four weights sum to 255 and every slot has a non-degenerate
   range;
9. the biome map/report agree with the stack and their hashes match;
10. each transition edge jump and non-band weight stays below 1/255, checked
    both from the report and by sampling the actual stack PNG.

Reference values: 344 tiles, 128² normal tiles, max seam error 1, 18.5 MB
checked in, stack 2048², macro/map 1024², six regions, five transitions. The
per-region stack coverage is roughly 12–14% each; the transition bands cover
the remaining ~12.5%. Region weight means are non-degenerate (for example the
arctic palette mixes snow, snowfield, cliff and rocky base, while the tropical
palette mixes forest leaves, laterite, grass and cliff rock). The material
texture budget is ~90.7 MiB (53.3 MiB for the two 20-layer arrays, 37.3 MiB for
the 2048² stack and 1024² macro, matching the Jotunheimen stack dimensions).
`biome-stats.json` records the live renderer values (20 library layers, 2048²
stack, 1024² macro/map, 15360 m extent, 8 texture units).

Headless QA (SwiftShader, 1600×900): 86k triangles, 4 draw calls, 47 resident
after priming, zero upload errors, and 81 analyzer passes with zero failures.
Material on/off `hf=1.41 → 13.12` and mean `95.5 → 68.4`; far-field `std=41.0`;
debug `std=20.1`; all five transition bands `std=17.2–32.7`; zero crack-test
magenta. `npm run test:biome` reports a maximum transition edge jump of ~0.0013,
below the 1/255 threshold.
