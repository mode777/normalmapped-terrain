# Spec Delta

## Purpose

The terrain renderer renders camera-centred clipmap terrain from a pluggable tile source, using one texture layout and shading path for procedural and pre-baked data.

## ADDED Requirements

### Requirement: Renderer consumes a tile source

The terrain renderer SHALL obtain height and normal tiles from a tile source keyed by LOD level and world tile coordinates, and SHALL NOT depend on whether tiles are generated procedurally or loaded from pre-baked assets. A source SHALL provide the same tile payload for the same key.

#### Scenario: Procedural and pre-baked sources share the renderer

- **WHEN** the renderer is configured with a procedural source or a pre-baked source
- **THEN** it SHALL render through the same geometry, texture layout, and shading path
- **AND** only the source, dataset configuration, and scene controls may differ

#### Scenario: Source swap preserves terrain behavior

- **WHEN** two sources provide equivalent height and normal data for the same region
- **THEN** the rendered terrain SHALL have the same silhouette, LOD transitions, and normal-map lighting

### Requirement: Tile texture contract

The renderer SHALL use two 2D array textures with one layer per LOD. Height layers SHALL be `cacheTiles × tileSize` square, with each world tile occupying a `tileSize`-square slot and storing normalized height. Normal layers SHALL use `cacheTiles × tileSize × normalScale` square, with each world tile storing object-space normals. The world tile size SHALL be `tileSize × baseSpacing × 2^L` for both maps.

#### Scenario: Height and normal maps cover the same world tile

- **WHEN** a height tile and a normal tile are uploaded for the same `(level, tx, ty)`
- **THEN** both SHALL cover the same world square
- **AND** their texel sizes SHALL differ by exactly `normalScale`

#### Scenario: Object-space normals are sampled without a tangent frame

- **WHEN** the fragment shader samples a normal tile
- **THEN** it SHALL decode `R = N.x`, `G = N.z`, `B = N.y`
- **AND** it SHALL light the fragment without a per-fragment TBN matrix

### Requirement: Toroidal cache addressing

The tile cache SHALL map world tile `(tx, ty)` to slot `(tx mod K, ty mod K)` and SHALL NOT shift texture contents when the camera moves. The shader SHALL reproduce the mapping from the render origin, reduced modulo the largest cache world size.

#### Scenario: Camera crosses a tile boundary

- **WHEN** the camera moves into a new world tile
- **THEN** only the newly required slots SHALL be uploaded
- **AND** the visible terrain SHALL remain continuous

#### Scenario: Long flight preserves tile phase

- **WHEN** the camera travels far enough to rebase the floating origin
- **THEN** the tile slot phase SHALL remain correct for every LOD
- **AND** no texture data SHALL be shifted to compensate

### Requirement: Per-LOD clipmap alignment

Each LOD SHALL snap its origin to its own vertex spacing. Rings above LOD 0 SHALL be padded to cover the parent square, clipped to that square in the fragment pass, and morph their outer cells into the next-coarser mesh.

#### Scenario: A ring stays rigid between snaps

- **WHEN** the camera moves by less than the current LOD's spacing
- **THEN** that LOD's origin and vertex positions SHALL remain unchanged
- **AND** the surface SHALL NOT swim

#### Scenario: Ring boundaries have no visible gaps

- **WHEN** the camera views a boundary between adjacent LODs at a grazing angle
- **THEN** the padded overlap, parent-square clip, and morph band SHALL cover the boundary
- **AND** no background-coloured crack SHALL appear inside the terrain silhouette

### Requirement: Procedural tile source

The procedural source SHALL generate tiles in workers from a seeded, pure height function and SHALL produce the same tile payload as any other source. Tile generation SHALL NOT run on the main thread.

#### Scenario: Procedural tiles stream without blocking the render loop

- **WHEN** the camera crosses a tile boundary
- **THEN** missing tiles SHALL be generated by workers
- **AND** tile generation SHALL NOT block the main render loop
- **AND** the visible 3×3 window SHALL remain resident after prefetch completes

### Requirement: Pre-baked tile source

The pre-baked source SHALL load a manifest and tile assets, validate that their spacing, tile size, normal scale, LOD count, and encoding match the renderer configuration, and report a clear error for missing or invalid assets.

#### Scenario: Matching manifest loads

- **WHEN** a valid manifest and its tiles are available
- **THEN** the source SHALL resolve tiles for every resident `(level, tx, ty)`
- **AND** the scene SHALL reach its ready state

#### Scenario: Configuration mismatch is rejected

- **WHEN** the manifest's spacing, tile size, normal scale, or LOD count differs from the renderer configuration
- **THEN** the scene SHALL fail with a visible, descriptive error
- **AND** it SHALL NOT render an incorrectly scaled terrain

#### Scenario: Missing tile is surfaced

- **WHEN** a required tile cannot be loaded or decoded
- **THEN** the failure SHALL be reported in the loading/status UI and console
- **AND** the scene SHALL NOT silently render incomplete terrain

### Requirement: Source-provided height query

A tile source MAY expose a CPU height query for camera clearance. When provided, the scene SHALL use that query for its terrain guard. A pre-baked source SHALL back the query with a checked-in coarse height grid rather than a GPU readback.

#### Scenario: Pre-baked scene keeps the camera above ground

- **WHEN** the camera descends toward the pre-baked terrain
- **THEN** the terrain guard SHALL use the source's CPU height query
- **AND** the camera SHALL remain above the surface without a GPU readback

### Requirement: Configurable renderer

The renderer SHALL accept configuration for base spacing, LOD count, tile size, normal scale, cache size, and height scale. It SHALL render both the procedural configuration (2 m base spacing, 10 LODs, 8× normals) and the pre-baked configuration (10 m base spacing, 6 LODs, 2× normals).

#### Scenario: Both configurations render

- **WHEN** the procedural page and the pre-baked page boot
- **THEN** each SHALL use its own configuration values
- **AND** neither page SHALL rely on hardcoded constants from the other

### Requirement: Failure visibility

If the renderer cannot obtain a required tile or the source configuration is invalid, the page SHALL surface the failure in its loading or status UI and in the console rather than rendering silently incomplete terrain.

#### Scenario: Boot failure is visible

- **WHEN** the tile source fails during initialization or while priming the visible window
- **THEN** the loading overlay or status chip SHALL show the failure
- **AND** the page SHALL leave a diagnostic message in the console
